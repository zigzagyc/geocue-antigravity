# Developer Onboarding & Secrets

This project uses **environment variables** and **native configuration files** to manage sensitive API keys. These files are **ignored by Git** to prevent leaks. To set up your development environment, you need to obtain these secrets securely from the project administrator or a secure vault (e.g., 1Password, Bitwarden).

## 1. Environment Variables (`.env`)
The app uses a `.env` file in the root directory for cross-platform keys (Firebase, Gemini).

**Setup:**
1.  Copy `.env.example` to a new file named `.env`.
    ```bash
    cp .env.example .env
    ```
2.  Fill in the values in `.env` with the secrets provided by the team lead.
    - `GEMINI_API_KEY`
    - `FIREBASE_ANDROID_API_KEY`
    - `FIREBASE_IOS_API_KEY`
    - `FIREBASE_MACOS_API_KEY`

## 2. Android Setup (`local.properties`)
Google Maps for Android requires a key in `android/local.properties`. This file is automatically generated by Android Studio but needs your specific API keys.

**Setup:**
1.  Open `android/local.properties`.
2.  Add the following line (ask team lead for the key):
    ```properties
    GOOGLE_MAPS_API_KEY=AIzaSy...
    ```

## 3. iOS Setup (`xcconfig`)
Google Maps for iOS typically reads keys from Configuration files.

**Setup:**
1.  Check `ios/Flutter/Release.xcconfig` (or your project's specific config file).
2.  Add the key:
    ```xcconfig
    GOOGLE_MAPS_API_KEY=AIzaSy...
    ```

## 🔐 Security Rules
- **NEVER commit** `.env`, `local.properties`, or `*.xcconfig` containing secrets.
- **NEVER send keys** via Slack/Email/Discord. Use a password manager or encrypted pastebin (e.g., 1Password Item Sharing, Bitwarden Send).
